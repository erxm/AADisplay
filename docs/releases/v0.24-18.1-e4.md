# v0.24#18.1-e4（versionCode 3018，上一版 e3 / 3017）

## 适配 Android Auto 18.1

- 修复升级到 AA 18.1 后模块完全没有生效：
  18.1 的 `LayoutInfo` 构造器新增了 `railOrientationFollowsRailWidget`（对象参数从第 6 位挪到第 7 位），
  原来写死位次的匹配器命中 0 个方法，`AaUiHook` 整个被跳过（自动打开、Coolwalk、投影钩子全部失效）。
  改为与版本无关的形状判断：前三项 int、第四项 int/enum、其后两个 boolean、
  第 6–9 位里恰好一个非 primitive、其余 boolean，17.8 / 18.1 都能命中。
- `args[5]` 仍是 `hasVerticalRail`，原有 hook 语义不变。

## 新增：AAP 直连路线（不依赖 Android Auto）

主界面新增「投屏路线」卡片，可在原版（hook gearhead）与 AAP 直连之间切换，切换立即生效：

- **USB**：插入 Android Auto accessory 后授权并连接；
- **无线**：蓝牙配对后 RFCOMM/WPP 握手，加入车机热点，再建立 TCP AAP 会话；
- **本地调试**：debug 构建下监听 TCP 与 `localabstract:aadisplay_hu`，配合 DHU 使用。

AAP 路线下虚拟屏由模块 App 创建（Route B），system_server 只负责任务托管、输入注入、
镜像与手机端悬浮窗；原版 `onCreateDisplay` / `onDestroyDisplay` 路径保持不变。
主界面实时显示连接状态（未连接 / 已连接（tcp/usb/…）），并提供连接与停止按钮。

认证沿用 AA 的车载证书（从已安装的 AA APK 提取），证书落在模块私有目录。

> 这条路线受 [lagXkjy/AADisplay](https://github.com/lagXkjy/AADisplay) 启发，连接思路与无线实现主要来自他的分支；
> 绝大多数场景下他的分支功能更完整、适用性更广，详见 [NOTICE-AAP.md](../../NOTICE-AAP.md)。

## 稳定性与体验修复

- **协程异常兜底**：system_server 侧建屏/销毁链路全部加 `CoroutineExceptionHandler`，
  未捕获异常不再打死 `system_server`。
- **建屏/销毁生命周期**：20s 建屏超时、销毁看门狗（`DelayDestroyTime + 30s`）、
  客户端 binder 死亡立即收尾；避免 App 被杀后虚拟屏泄漏到重启。
- **悬浮窗**：`removeViewImmediate` 同步摘窗，多实例兜底清理；旧会话的 60s 倒计时
  不会再拆掉之后建立的新会话。
- **悬浮球尺寸**：修正 inflate 密度，原版路线下悬浮球不再缩到 59px（恢复 161px）。
- **监听与收尾**：AAP 的 TCP/localabstract 监听改为常驻 accept 循环，
  重连不再 `EADDRINUSE`；收尾时不会误 force-stop gearhead。
- **车机服务器**：启动/停止改用 signature 级权限广播，root 兜底走
  `am start-foreground-service`；入口移到高级设置页。

## 已知限制

- AAP 路线仅在 DHU（TCP/localabstract）上实测；真实车机的 USB / 无线尚未验证。
  AAP 无线要求车机走标准 AA 无线流程（手机加入车机热点，不是 Wi-Fi Direct/P2P）。
- 无线首次连接可能弹出 Android 的“连接到此设备”确认框，批准一次即可。
- DHU 请使用原版 `desktop-head-unit.exe` + `800x480 / 170dpi`；`800x533` 补丁版
  窗口比视频多 53px，底部会出现绿条（DHU 自身渲染问题，不是投屏画面）。
- **装完请重启手机**（system_server 侧 hook 与资源需要重新加载）。

实测环境：HyperOS `3.0.307.6`（Android 16）+ Android Auto `18.1.664444-release` + DHU。
技术细节见 [CHANGELOG.md](../../CHANGELOG.md)。
